APPROVAL BEHAVIOUR — the notable negative result

$ cursor-agent          # interactive, no flags

Every MCP call proceeded. Nothing was auto-rejected, and `--force` was neither passed nor
needed. This is the direct contrast to `cursor-approval-recheck.txt`, where the same
account and the same build auto-rejected every call in `-p` print mode with
`User rejected MCP: lambo-lambo_derive`.

So the per-call approval gate is a property of non-interactive print mode, not of the
client, the account, or the server. Interactive approval is the supported path; `--force`
is the workaround for scripting, and it is the only path that needs bounding.

The agent also called its schema-discovery step first ("Explored available MCP tools
cockroachdb-cloud · list_databases / · select_query") before issuing either call.
