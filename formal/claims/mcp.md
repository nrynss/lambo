# Claims audit: `docs/reference/mcp.mdx`

This file audits the MCP tools reference page against the Lean models in
`formal/LamboProofs/`, the Rust in `src/`, and the tests. The site copy,
`site/src/content/docs/mcp.mdx`, carries the same shared prose and is covered
by the same rows.

## Method

- **Page audited:** `docs/reference/mcp.mdx` at commit `8cede2ae` (`origin/main`
  on 2026-11-22). Every `line` below is a line number in that version of the
  page. The fixes this audit made are on branch `docs/mcp-claims-audit`.
- **Date:** 2026-11-22.
- **Models:** all 28 models were in step with their Rust at that commit:
  `python3 -I scripts/formal/check-model-drift.py` reported no drift.
- **What counts as a claim:** every sentence that promises behaviour an agent or
  operator could rely on: ordering, limits, defaults and counts; when something
  is refused or accepted; error and refusal semantics; what a field means;
  timing ("after", "before", "once", "within"); and anything with always, never,
  must, only, at most, exactly or guarantees. Pure navigation is skipped, and so
  are examples, unless an example asserts behaviour. A sentence whose parts have
  different backing is split into rows with `a`, `b` and `c` suffixes.
- **Quotes:** each `claim` cell quotes the page verbatim, at most 25 words.

Each row has exactly one class:

| Class | Meaning |
|---|---|
| PROVEN | A theorem's statement entails the claim. The row names the theorem and its model file. A related theorem is not enough. The notes say what the model abstracts away that the claim depends on, such as exact arithmetic in place of `f64`, or no concurrency. |
| TESTED | A Rust test asserts the claim. The row names the test. |
| CODE-ONLY | Reading the code confirms the claim, but no theorem or test pins it. The row cites `file:item`. |
| COMMENT-ONLY | Only a doc or module comment says so, and the check against the code was not finished. A comment is not code. The row cites the comment. |
| CONTRADICTED | A theorem or the code says otherwise. The notes say what differs. The resolution is listed in [Contradicted claims](#contradicted-claims). |
| NOT CHECKABLE | The claim is about quality, statistics, history, or the behaviour of other software. The notes say why. |

Where it helps, the notes of a row that is not PROVEN say what theorem or test
could pin it ("Could pin: ...").

A backing cell names a test or a theorem as `name` in `file`, and code as
`file:item` or `file:line`. Paths are relative to the repository root; a bare
`.lean` name is in `formal/LamboProofs/`.

The rows were extracted and checked by five agents, one per range of the page.
That first pass checked a sample of the CONTRADICTED rows and of the cited
theorem statements again by hand before the page was changed, but did not
record how many. An independent review then re-read 50 of the 53
contradictions and sampled 41 PROVEN, 22 CODE-ONLY and 24 TESTED rows; the
other rows rest on the first pass alone. Its findings were worked through by hand on 2026-11-22: 61 rows
were checked again against the code, the tests or the theorem statement (every
row the review named, and every CODE-ONLY row that cited a comment or said its
check was unfinished), and 18 of them changed class. Each of those rows now
cites code, a test or a theorem, so no row is COMMENT-ONLY.

**Anchors (2026-11-23).** Both copies of the page now carry each PROVEN,
TESTED and CODE-ONLY row's backing as invisible MDX anchors next to the
sentence, item or table it backs: `lean:` for PROVEN, `test:` for TESTED,
`code:` for CODE-ONLY, and `const:` where a pinned constant backs a number.
`scripts/docs/check-doc-anchors.py` resolves every anchor in CI and requires
both copies to keep their `lean:`, `const:`, `code:` and `test:` anchors. This
file records the audit as it was done; the anchors are what keep the page
true from here on, and where the two differ, the anchors are current. While
anchoring, each row's backing was checked again against the page as it now
reads, many CODE-ONLY rows gained a test beside their code, and eleven
sentences were corrected where the code said otherwise (Q-05, Q-21, Q-43,

## Terms

The page used these terms in more than one sense, or differently from the
model or the code. The fixed page uses each in one sense.

| Term | Before | Now |
|---|---|---|
| ack, admitted, applied | "Acked" stood for both admitted writes and `dropped` ones ("no acked write is lost"); "the acknowledgement admits the write". | The ack answers every write call. An *admitted* write is one the ack did not drop; only admitted writes get an intent and survive a clean shutdown. *Applied* means in the server's graph (the receipt state), not in the store. This matches the drain model (`Drain/*.lean`), whose theorems quantify over admitted jobs. |
| `pending`, `pending_replay` | "If it is still pending" and "every intent stays pending" covered both states. | Both states are named where either can occur. |
| holder, hub | The lease-holding process was called both. | *Holder*, as in `Lease.lean`. |
| session (Lambo) and MCP session | The HTTP connection cap was "concurrently live MCP sessions". | "MCP connections (transport sessions, not Lambo sessions)". |
| server (scope of a bound) | "A server holds 16 waits", "the ceiling across every agent on the server". | Per session, which is where the code keeps the write pipeline. |
| dropped, discarded | `dropped` is a receipt state, and "dropped rather than flushed" also named dead-lettered or degraded losses. | *Dropped* is only the receipt state; flush-side losses are *discarded*. |
| ordinary | "Ordinary query" (not a dependency question), "ordinary hit" (neither Canonical nor Venerable) and "ordinary memory" (status `None`). | *General query*, as `Dispatch.lean` calls it; "a hit that is neither Canonical nor Venerable"; "status `None` (ordinary memory)", the `Canon.lean` status. |
| exact content | Used for references that actually match by canonical key. | "Content, matched by canonical key". |
| stale-citation line | A second name for the rests-on line, clashing with the hot list's Stale condition. | *Rests-on line*. |
| top hit, first block | The truncation rule was headed "top hit" but triggers on the first rendered block. | *First block*, as in `Fit.lean`. |
| scope | Also used for "applies to" in a heading. | Kept for the `scope` argument and layers only. |
| 16 KB | Meant 16,384 bytes. | 16 KiB (16,384 bytes). |
| measured baseline | The code's null median cosine. | Glossed once. |

Not changed, and worth a follow-up: "score" still means both a hit's final
score and a leg's score; "holder" is also used for the owner of a soft lock
("who holds the node"); "merged by similarity" means a new node joined by a
`Semantic` edge, not one node.

## Claims a new theorem should pin

By model. Each is a claim the page makes that today rests on a test or the code.

- **`Resolve.lean`:** a general theorem that every non-loopback HTTP bind with
  no credential is refused (T-07; only `bind_refused_after_build`, one instance,
  exists).
- **`Drain/Close.lean`:** that a held write's intent is durable once a flush takes
  it, across a restart (S-87a; `outage_holdsW` and `held_at_closeW` now pin
  S-87b and S-91); that a new serve's admissions can overtake writes owed from an earlier one (T-44,
  D-64b, as a counterexample theorem over `serveR` with live admission); the
  `image_config` block reason (S-104, S-135); that every owed row is eventually
  replayed when the embedder answers (S-120).
- **`Receipts.lean`:** the wait caps (16 per session, 8 per agent) and that a
  capped wait answers at once (S-63, S-64); receipt routing by destination, so
  that another agent or a layer-sharing session gets `forbidden` and an
  unrelated pipeline `restart_lost` (S-58, S-102).
- **`Hotlist.lean`:** that the contradicting concept beside a forced hit is
  emitted and holds no slot (`companion_emitted`; Q-46, Q-50b); the "at most
  twice `top_k`" bound for companions (Q-49); that a hit's score does not read
  its hot-list payload, so a warning moves no hit (Q-53a).
- **`Confidence.lean`:** that a traversal answer leaves `TopLegs` at its default,
  so it has no `confidence` (R-42d).
- **`Fit.lean`:** that `defaultTokenCount` gives a downward-closed fit test, so
  `context` is the longest fitting prefix (R-45b); that `ceil(b / 3.5)` in `f64`
  equals the model's `(2b + 6) / 7` for every byte count a request can carry
  (R-47a).
- **`Canonical.lean`:** that an id-shaped name (a UUID or eight hex characters)
  has no name key (D-08); the invisible-character strip, so that texts differing
  only by allowed invisible characters share a key (T-52).
- **`Conflict/Contradiction.lean`:** the rests-on rule, a hit warned when a concept it cites
  directly is contradicted (Q-71 to Q-85); that `contradictionAt` is unchanged
  by the target's status (Q-33).
- **`Gc.lean`:** `contradictsPromoted` derived from the edges and statuses
  rather than taken as an input (Q-63); that a concept contradicting a
  Venerable or Canonical one stays protected after the warning lapses (Q-64).
- **`Canon.lean`:** that a full Canonical budget evaluates no Stage 3 window,
  not only that it promotes nobody (S-17b).
- **`Cite.lean`:** the refusal step, so that a batch citing and contradicting
  one concept is refused, not only that a batch passing the check does neither
  (D-33).
- **`Reserve.lean`:** that reservations are empty after a restart (S-08).
- **`Flush.lean`:** the flush-lag bound (S-67, S-68, S-72); the model has no
  clock.
- **`Supersession.lean`:** the cosine threshold and the repository-scope
  condition for a suspected pair (Q-105b).
- **New models:** the local endpoint's forwarding and socket rules (T-13, T-22
  to T-30); that one `lambo serve` process is one lease holder, so the store's
  exclusion is the process's (T-02); dependency-question anchor resolution
  (Q-06 to Q-20), which `Dispatch.lean` takes as an input.

## Re-verify on the rmcp bump (#332)

These sentences describe rmcp 3.1.2, the MCP library, rather than Lambo's own
code. Check each again when rmcp is upgraded.

- Errors table, first row: "a value of the wrong type is described by its
  type, not by its field" (T-64b). rmcp passes the arguments to a plain
  `serde_json::from_value` (`src/handler/server/tool.rs`, `Parameters`).
- `lambo_derive_image`, *Lambo's refusals never repeat your payload*: "that
  error quotes the value back to the caller" (D-143). Same serde path.
- Errors intro: "Parameter errors are tool results too." rmcp turns an
  argument deserialization failure into an `isError` result
  (`into_tool_argument_error` in `src/handler/server/router/tool.rs`); an
  unknown tool stays a JSON-RPC error ("tool not found", T-62).
- `lambo_derive_image` intro: "the MCP library logs every request it receives at
  debug level" (D-131b).
