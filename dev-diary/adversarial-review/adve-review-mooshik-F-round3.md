## New findings

### F-R3-1 (P3, advisory) — `SqliteStore::seed` is a second `sessions.embedding_dim` writer with no quarantine, so the property's residual list is one surface short

- **Evidence:** only two statements in the adapter write `sessions.embedding_dim`. One is `set_embedding` (`sqlite.rs:2049`), now correctly preceded by the widened quarantine. The other is `seed` (`sqlite.rs:518-531`), whose `INSERT … ON CONFLICT (session_id) DO UPDATE SET … embedding_dim = excluded.embedding_dim` restamps the contract with **no quarantine at all** — and `seed` upserts rather than replaces, so concepts already in the session but absent from the new snapshot are never seen by `enforce_concept_vector_widths`. Reproduced from an external crate (`default-features = false, features = ["store-sqlite", "fixtures"]`), two `seed` calls, no direct SQL (PROBE G): seed dim=4 with a 4-wide concept, then seed dim=3 with a 3-wide concept over the same session → contract `dim=3`, widths `[Some(3), Some(4)]`, both read surfaces `Backend` session-wide — round 2's F-R2-1 terminal state exactly, with the same blast radius. It also diverges from the reference implementation `seed`'s own doc invokes for parity: `MemoryStore::seed` **replaces** the session (`store/memory.rs:105-108`), so the surviving-old-concept precondition cannot exist there. SQLite's merge semantics are what make the orphan reachable.
- **Impact:** **Behaviour: not a production defect.** `seed` is not on the `GraphStore` trait; it is an inherent `pub async fn` gated `#[cfg(feature = "fixtures")]`, and `fixtures` is deliberately excluded from `default` and from `ship`. Every in-tree caller is a test module; the two non-test callers seed a `MemoryStore`. So no shipped binary and no in-tree path can reach this. **Claim: overstated by one residual.** The property statements name exactly one residual (an externally edited database); `seed` is a write through this adapter and is a second, unnamed. Applied mechanically, round 2's blocking criterion is met. Held at P3 on three grounds: the surface is test scaffolding rather than the production trait boundary rounds 1 and 2 both attacked; the property that operators and workstream B actually inherit — the trait surface holds — is *true*, and I could not falsify it across nine orderings; and the shape is arguably outside `seed`'s stated contract ("Seed a prebuilt snapshot directly (fixtures track)"), which reads as a fresh-database operation. A reviewer who weighted the absoluteness of the wording over the reachability of the surface could reasonably call this P2; I do not, and I would not re-block a third round on it.
- **Suggested remediation (either is a one-liner):** name it — add `seed` beside the hand-edited-database residual at the three property statements, noting that `seed` upserts where `MemoryStore::seed` replaces; or close it — run the same quarantine statement in `seed` before `upsert_concepts`. Naming it is sufficient at this severity.

## Positive observations

- **The fix is the smallest correct one, and it is provably non-regressive.** One predicate, one extra bind, one statement, and a monotonicity argument that closes the obvious worry. The statement ordering — quarantine before the `sessions` UPDATE — is what makes it work at all, and it is correct.
- **The remediation ran the falsification test on itself and reported the output.** The quoted failure reproduces character for character.
