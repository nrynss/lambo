## Provision PostgreSQL before restarting the writer

<Badge text="Breaking change" variant="danger" />

Stop the writer. With the v0.16.0 binary and your existing store configuration, run
`lambo --config lambo.toml provision`. Restart the writer after provisioning succeeds.
Provisioning replaces the canonical-key index with one that indexes a fixed-width digest.
Matching still uses the full keys. The writer refuses to attach while the legacy index
remains.

## Update configuration and source builds

<Badge text="Breaking change" variant="danger" />

Remove `canonization_min_peer_count` if your configuration sets it. If it selects `bedrock`
or `titan`, choose a [supported embedder](/lambo/config/#embedder) and see
[how to re-embed stored concepts](/lambo/cli/#re-embed-stored-concepts) if you are changing
an existing session’s embedding contract. Building from source requires Rust 1.100 or later.

## Recover queued writes after a rejected replay

<Badge text="Enhancement" variant="note" />

Startup replay isolates a rejected write and reports `failed` once the store confirms that
outcome. Later intents stay `pending_replay` and can apply on a subsequent restart. Lambo
refuses new writes while replay is active, while outcomes await confirmation, or while
recovery requires a restart. See
[Troubleshoot missing memory](/lambo/troubleshoot-missing-memory/).

## Preserve the latest Elasticsearch mirror

<Badge text="Enhancement" variant="note" />

Recall repairs rebuild from the snapshot used to check the sync marker and preserve the
latest writer’s mirror state. Large flushes send vector changes in bounded bulk requests.

## Load the portal embedder on the first vector recall

<Badge text="Behavior change" variant="caution" />

`lambo serve-web` opens the portal before loading model weights. The first recall that needs
a query vector loads the embedder and concurrent recalls share that load. Use
`--no-embedder` or `[web] embedder = false` to run the portal with keyword and recent recall
only.
