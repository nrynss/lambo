Lambo uses Lean 4 to model parts of its memory engine, including recall, graph updates, and write durability. You can use the proofs to check a rule across all inputs or event sequences that satisfy the model's assumptions.

## How the models work

Lean definitions describe algorithms or state transitions. Theorems state what follows from those definitions. For example, the lease model represents acquire and release as atomic operations and proves that the fencing token never decreases across a sequence of those operations. {/* lean: Lease.token_mono */}

Each model's header identifies the Rust behavior it represents and the assumptions it makes. For the full theorem inventory and source map, refer to the [Lean proof README](https://github.com/nrynss/lambo/blob/main/formal/README.md#what-is-modelled-and-what-each-file-proves).

## How the checks connect to Rust

| Check | What it checks |
| --- | --- |
| Lean build and axiom audit | CI checks the proofs with the pinned Lean toolchain, rejects proof placeholders, and limits audited theorems to Lean's standard axioms. |
| Rust constant tests | Tests compare selected Lean constants, such as the canonization thresholds for coverage and blast radius, with the Rust definitions. {/* const: MIN_COVERAGE, MIN_BLAST_RADIUS */} |
| Differential oracle | Lean evaluates selected definitions on reproducible inputs and exports their expected outputs. A Rust test runs the corresponding functions on those inputs and compares the results. {/* test: src/formal_oracle_tests.rs oracle */} |
| Model drift check | A fingerprint in `formal/models.toml` records the mapped Rust source when someone last reviewed the model against it. A changed fingerprint prompts another review. |

The oracle caught a ranking bug in reciprocal rank fusion. Rust sorted `+0.0` and `-0.0` separately, bypassing the tie-breaker. The replay now checks that these zero scores tie. {/* test: src/recall/candidates.rs rrf_zero_scores_tie_break_whatever_the_sign_of_zero */}

## Model boundaries

Each proof applies to the Lean definitions under their stated assumptions. The Rust replay checks agreement for the exported cases. Changes in mapped Rust source still call for review of the model and its assumptions.

Some scoring models use exact arithmetic, so their bounds apply to that arithmetic. The lease model assumes atomic store operations. Models that describe concurrent work cover the interleavings represented by their event sequences. Canonization starts with measurements such as coverage and blast radius supplied by the store.

See [End to end](/lambo/end-to-end/) to follow those components through a running session.

## Run the checks locally

Install Lean with `elan` and make `lake` available on your `PATH`. You also need Cargo and Python 3.11 or later. Run the commands from the repository root. The `formal/lean-toolchain` file selects the Lean version.

```bash
(cd formal && lake build --wfail)
bash scripts/formal/check-oracle.sh
cargo test --locked --lib formal_oracle_tests::oracle
cargo test --locked --lib formal_constants_tests
python3 -I scripts/formal/check-model-drift.py
```

To replay the Candle batching cases, add `--features embed-candle` to the oracle test command.

For the steps to review and update a model after a Rust change, refer to [Keeping the models in step with the Rust](https://github.com/nrynss/lambo/blob/main/formal/README.md#keeping-the-models-in-step-with-the-rust).
