## Release comparison method

Version tests start each build from an independent copy of the same store backup. Compare
results within each test. Hardware, store snapshots, and layer configuration vary across
reports. The v0.6.0 cutover measures two session layouts on one binary.

| Measurement | Method | What to compare |
|---|---|---|
| Write replay | Reconstruct historical writes, add reworded variants, and submit them through stdio. | Receipt outcomes, created concepts, and semantic edges. |
| Sequential latency | Alternate the same recall queries between two HTTP servers. Time derive calls through acknowledgement and receipt. | Client latency percentiles and ranked recall results. |
| Concurrent load | Run eight or 16 independent MCP clients with a seeded mix of recalls, derives, actions, and stats. | Tail latency, failed writes, and receipt outcomes after the queue drains. |
| Offline commands | Time session load and canonization dry runs with Hyperfine. Reverse release order for the second batch. | Wall-clock time and agreement between dry-run reports. |

## Read the measurements

The 50th percentile (p50) is the median. The 99th percentile (p99) describes the slow end
of the sample. Client latency includes the call through HTTP. Server latency comes from
the serving process's log.

A derive acknowledgement means the server admitted the write into its queue. Use the
applied receipt to measure completion. Server-side apply lag starts at acknowledgement
and ends when the write completes.

## Run a release comparison

Use two scratch writers on loopback ports. Provision each copy of the backup with the
release binary that will serve it. Use matching embedder settings and the same query set
for both versions. The benchmark drivers write to the scratch databases.

For more information, refer to the [load test harnesses](https://github.com/nrynss/lambo/blob/main/scripts/loadtest/README.md)
and the [Metal commands and run settings](https://github.com/nrynss/lambo/blob/main/evidence/0.16.0-vs-0.15.0-metal/README.md#reproduce-the-measurements).
The published reports include sanitized measurements. Run the same method with your own
store backup and queries.

See [Evidence and evaluation](/lambo/evidence/) to find cross-store tests, durability tests,
and the multi-agent usage audit.
